# Code style

## Naming

Spell out words in new or renamed identifiers, including variables, fields,
functions, methods, types, traits, modules, and constants. Use descriptive
names such as `expression` for an expression value.

## Rust documentation

Document every new or modified Rust type, trait, function, and method with
Rustdoc, including internal helpers. Use multiline `/** ... */` blocks with a
leading `*` on each content line. Use `/*! ... */` blocks for crate and module
documentation. Explain the contract and any relevant errors or invariants.
